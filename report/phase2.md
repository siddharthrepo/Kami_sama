# Phase 2 — Model Implementation, Pretraining, and Evaluation

Language Models and Agents, Monsoon 2026 — Individual Project.

Two decoder-only Transformers, built from PyTorch primitives and pretrained
independently: **Model H** on Hindi (higher-resource) and **Model L** on Nepali
(lower-resource). No data, vocabulary, weight or optimizer state is shared between them.

Every number in this report is reproduced from the JSON artefacts under `report/hindi/`
and `report/nepali/`; the tables in §5–§7 are generated by `scripts/compare_models.py`
rather than typed, so the prose cannot drift from the run.

---

## 0. How Phase 1 fixed this model's shape

The architecture in §2 is not free of Phase 1: the vocabulary chosen there determines how
much of the parameter budget is left for the Transformer itself, so it is worth restating
the constraint before the numbers.

Under weight tying the embedding matrix is `vocab_size × d_model` and is counted once, so
vocabulary trades directly against depth. At `d_model = 448` the rest of the model costs
17,130,176 parameters, leaving 7,869,824 of a ~25M budget for the table — a ceiling of
17,566 pieces. Phase 1 selected **16,000** for both languages on exactly that basis
(`report/phase1.md` §6.2): it is the lowest-fertility candidate that fits, and the next
size up (24,000) would have totalled 27,882,176 parameters, 11.5% over target.

The consequence for this phase is that the embedding is 7,168,000 parameters — 29.5% of
the model — and the remaining 16,900,800 buy 7 layers at width 448. Had the vocabulary
been 24,000, the same budget would have allowed roughly two fewer blocks.

The price paid is fertility: 1.259 tokens/word for Hindi and 1.381 for Nepali, against
1.216 and 1.310 at 24,000. §5 shows why that price is worth paying, and why it makes
perplexity a misleading number to compare across the two models.

## 1. Architecture

Implemented in `lma/model.py` and `lma/attention.py` from `nn.Linear`, `nn.Embedding`,
`nn.LayerNorm`, `nn.Dropout`, `nn.GELU`, `nn.Module`, `nn.ModuleList` and `nn.init`
only. No `nn.Transformer*` module, no HuggingFace class, and no
`F.scaled_dot_product_attention` — the attention computation is written out so that
every tensor operation in the forward pass is visible.

Shapes below use `B` batch, `T` sequence length, `d` model dimension, `h` heads,
`d_k = d/h`.

### 1.1 Input representation

**Token embeddings.** `nn.Embedding(vocab_size, d)` maps ids to dense vectors:
`(B, T) → (B, T, d)`.

**Positional embeddings — learned absolute.** Self-attention is permutation invariant:
without position, `softmax(QKᵀ/√d_k)V` computes the same set of outputs for any
reordering of the input. Position is injected by a second table
`nn.Embedding(max_seq_len, d)` indexed by `arange(T)`, broadcast over the batch and
**added** to the token embeddings.

*Why learned absolute, over sinusoidal or RoPE.* It is the scheme whose every operation
can be explained end to end without appealing to a frequency argument, and it makes the
context ceiling explicit rather than implicit. The table has exactly `max_seq_len = 512`
rows, so there is no vector to look up at position 512 or beyond — the model cannot be
run on a longer sequence at all, and `lma/model.py` raises rather than silently
truncating. Sinusoidal encodings would extrapolate to longer sequences numerically while
degrading in quality, and RoPE would too; the hard failure is the more honest behaviour
for a model that was never trained beyond 512.

The sum is passed through embedding dropout (`p = 0.1`).

### 1.2 Multi-head causal self-attention

Per block, from input `X ∈ R^(B×T×d)`:

1. **Projection.** One fused `nn.Linear(d, 3d)` produces Q, K, V together, then splits
   into three `(B, T, d)` tensors. A single matmul rather than three is a pure
   efficiency choice; it is mathematically identical to separate `W_Q`, `W_K`, `W_V`.

2. **Head reshape.** `(B, T, d) → (B, T, h, d_k) → (B, h, T, d_k)` by `view` then
   `transpose(1, 2)`. The transpose is what makes each head a contiguous batch dimension
   so the following matmul operates per head. With `d = 448` and `h = 7`, `d_k = 64`.

3. **Scores.** `Q @ K.transpose(-2, -1) / sqrt(d_k)` → `(B, h, T, T)`.

   *Why 1/√d_k.* For Q, K entries with unit variance, the dot product over `d_k` terms
   has variance `d_k` and therefore standard deviation `√d_k`. Feeding scores of that
   scale into softmax drives it towards a one-hot distribution, where the gradient is
   almost everywhere near zero and learning stalls. Dividing by `√d_k` restores unit
   variance and keeps the softmax in its responsive region. At `d_k = 64` the unscaled
   scores would be 8× too large.

4. **Causal mask.** An upper-triangular mask built with `torch.tril` is applied with
   `masked_fill(mask == 0, float("-inf"))` **before** the softmax, so that position `t`
   attends only to positions `≤ t`. Adding `-inf` pre-softmax sends those weights to
   exactly zero post-softmax; masking after the softmax would leave a renormalisation
   error. §3 verifies this empirically.

5. **Weights and values.** `softmax(scores, dim=-1)`, attention dropout (`p = 0.1`),
   then `@ V` → `(B, h, T, d_k)`.

6. **Merge.** `transpose(1, 2).contiguous().view(B, T, d)`, then the output projection
   `W_O = nn.Linear(d, d)` and residual dropout. The `contiguous()` is required because
   the transpose leaves a non-contiguous view that `view` cannot reinterpret.

### 1.3 Transformer block

Each of the 7 blocks is **pre-norm**:

```
x = x + Dropout(Attention(LayerNorm(x)))
x = x + Dropout(FFN(LayerNorm(x)))
```

The feed-forward network is `Linear(d, d_ff) → GELU → Linear(d_ff, d)` with
`d_ff = 4d = 1792`.

*Why pre-norm.* The residual stream is an unbroken identity path from the embeddings to
the final norm, so gradients reach layer 0 without passing through a normalisation at
every step. Post-norm places a LayerNorm on the residual path itself, which at this
depth needs a far more carefully tuned warmup to remain stable. The project had one
training run per language and no budget for a restart, which made the more forgiving
choice the correct one.

A final `LayerNorm` follows the stack — necessary under pre-norm, because the last
block's output has never been normalised.

*What would break if removed.* Without the residual connections, gradient signal decays
multiplicatively through 7 blocks and the lower layers barely train. Without LayerNorm,
activation scale drifts between layers and the fixed learning rate is wrong for most of
them. Without the FFN, the model is a stack of linear mixing operations with no
per-position non-linearity, and cannot represent token-local transformations at all.

### 1.4 Output head and objective

A linear projection `d → vocab_size` produces next-token logits, **tied** to the input
embedding matrix (the same tensor, not a copy).

*Parameter saving.* Untied, the head would cost a second `16,000 × 448 = 7,168,000`
matrix, taking the model from 24,298,176 to 31,466,176 parameters — the tying saves
**22.8%** of the untied total. Verified in the checkpoint: `tok_emb.weight` and
`lm_head.weight` share one storage pointer, and `config.json` books `lm_head` at 0
parameters so it is not double-counted.

Training objective is causal language modelling: cross-entropy between the logits at
position `t` and the token at `t+1`, averaged over all positions, computed in one
`F.cross_entropy` call on the flattened `(B·(T-1), vocab)` logits.

## 2. Configuration and parameter count

Identical shape for both models. Both Phase 1 vocabularies are 16,000, so nothing forces
the architectures apart, and holding shape constant means any difference in §5–§7 is
attributable to the corpora rather than to the model — which is the comparison this
project exists to make.

| | Model H (Hindi) | Model L (Nepali) |
|---|---|---|
| Vocabulary | 16,000 | 16,000 |
| Layers / heads / `d_model` | 7 / 7 / 448 | 7 / 7 / 448 |
| `d_head` / `d_ff` | 64 / 1792 | 64 / 1792 |
| Context length | 512 | 512 |
| Dropout (resid / attn / embd) | 0.1 / 0.1 / 0.1 | same |
| **Total parameters** | **24,298,176** | **24,298,176** |
| Non-embedding | 16,900,800 | 16,900,800 |

Breakdown: token embedding 7,168,000 · positional 229,376 · blocks 16,899,904 ·
final norm 896 · tied head 0.

### Depth/width justification

`448 / 7 = 64.0`, the same aspect ratio as GPT-2 small (`768 / 12`). Two alternatives
were costed at the same budget:

| Configuration | Parameters | Aspect ratio |
|---|---|---|
| 384 × 10 layers | 24,092,928 | 38.4 |
| **448 × 7 layers** | **24,298,176** | **64.0** |
| 512 × 5 layers | 24,218,624 | 102.4 |

512 × 5 is too shallow to compose much: with only five blocks there is little room for
the diffuse → specialised → diffuse progression §7 actually observes. 384 × 10 is a
defensible deeper option, but on a single T4 it costs more sequential layer launches per
step for no expected gain at this scale, and the wall-clock budget was one ~3.5-hour
session per language. 448 also divides evenly into 7 heads of 64 — the width at which
attention kernels are efficient, and a common `d_head` across scales.

## 3. Causal masking, verified empirically

The spec asks for evidence that the model cannot see the future, not an assertion.
`tests/test_causal.py` provides five checks, all passing:

| Test | What it establishes |
|---|---|
| `test_future_token_cannot_change_past_logits` | Changing token `t+1` leaves the logits at position `t` **bit-identical** |
| `test_attention_mass_is_confined_to_the_past` | Every row of every attention matrix places exactly 0.0 on positions `> t` |
| `test_prefix_gives_same_logits_as_full_sequence` | Feeding a prefix yields the same logits as feeding the full sequence and slicing |
| `test_shuffling_positions_changes_output` | Positional information is actually used (a permutation changes the output) |
| `test_the_prefix_check_has_teeth` | The prefix check fails on a deliberately non-causal model — the test can detect the bug it claims to exclude |

The last one matters: a passing causal test is worthless if it would pass on a broken
model too, so the suite includes a negative control.

This is visible in the figures as well. In every panel of
`report/*/figures/*_attention_layer*.png` the entire upper-right triangle is uniformly
zero — the mask, drawn.

## 4. Pretraining

Both models trained independently on Kaggle T4, `scripts/pretrain.py`.

| | Value |
|---|---|
| Optimizer | AdamW, β = (0.9, 0.95), weight decay 0.1 |
| Weight decay applied to | matrices only; biases, LayerNorm and embeddings excluded |
| Schedule | linear warmup 500 steps → cosine decay to `0.1 × peak` |
| Peak / final LR | 6e-4 / 6e-5 |
| Gradient clipping | 1.0 (global norm) |
| Tokens per step | 32,768 (micro-batch 32 × accumulation 2 × 512) |
| Steps | 16,000 |
| **Tokens seen** | **524,288,000** |
| Mixed precision | fp16 with gradient scaling |
| Seed | 1337 |

**Epochs: 0.710 (Hindi), 0.730 (Nepali).** Both corpora exceed the training budget, so
no document is seen twice. This is the structural reason overfitting cannot occur here,
and §5 confirms it: test loss is marginally *below* validation for both models.

**Checkpointing.** Every 1,000 steps, plus a `best.pt` on validation improvement. Each
checkpoint carries all five mandated fields — model weights, optimizer state, scheduler
state, training step, and configuration — plus the four RNG streams (Python, NumPy,
torch, torch.cuda) and the AMP scaler state, so a resumed run continues the *same*
trajectory rather than a statistically similar one.

The scheduler is stateless by construction: `learning_rate_at(step)` is a pure function
of the step, so there is no hidden optimizer state to lose. `scheduler_state()`
serialises it explicitly anyway, since the spec requires scheduler state in the
checkpoint.

Batch order is likewise a pure function of `(seed, micro_step)` via
`np.random.default_rng([seed, micro_step])`, which makes resume bit-exact rather than
approximate.

## 5. Intrinsic language-modelling metrics

Both models evaluated on their own held-out splits, full-split (99.95%+ coverage,
`scripts/eval_lm.py`).

| | Model H (Hindi) | Model L (Nepali) |
|---|---|---|
| Validation cross-entropy (nats) | 3.3476 | 3.8117 |
| **Validation perplexity** | **28.43** | **45.23** |
| **Validation bits per byte** | **0.4930** | **0.4527** |
| Test cross-entropy (nats) | 3.3402 | 3.8087 |
| Test perplexity | 28.23 | 45.09 |
| Test bits per byte | 0.4916 | 0.4527 |
| Tokens scored (validation) | 15,351,808 | 14,819,328 |

### The two metrics disagree, and that is the finding

Perplexity says Model H is far better — 28.4 against 45.2, a 59% gap. Bits-per-byte says
Model L is **better** — 0.4527 against 0.4930. Both are correct; they measure different
things, and the disagreement is exactly what the spec's request for BPB is designed to
expose.

The cause is tokenizer geometry:

| | Model H | Model L |
|---|---|---|
| Fertility (tokens/word) | 1.259 | 1.381 |
| Characters per token | 3.992 | 4.586 |
| **Bytes per token** | **9.796** | **12.146** |
| Bytes per character | 2.454 | 2.648 |
| **Bits per character** | **1.2099** | **1.1991** |

A Nepali token is harder to predict (3.81 nats against 3.35) but carries substantially
more text — 12.15 bytes against 9.80 — because Nepali words are longer (6.33 characters
per word against 5.03), its morphology being more suffix-heavy. More entropy spread over
more bytes nets out to fewer bits per byte.

Normalising all the way to **bits per character** puts the two within 0.011 bits of each
other: 1.2099 and 1.1991.

**The honest conclusion is not that Model L is better.** BPB equalises tokenizers, not
languages, and Nepali text may simply be more predictable per character — its corpus
draws on three sources against Hindi's four, and is correspondingly more homogeneous.
What the comparison does establish is that **perplexity dramatically overstates the
resource gap**: a 59% difference in perplexity corresponds to a 0.9% difference in bits
per character.

The training curves agree. `report/figures/validation_loss_comparison.png` shows the gap
narrowing from 0.66 nats early to 0.47 nats at convergence — the lower-resource model
closing on the higher-resource one as both saturate their shared token budget.

### Gap discussion (data, script, tokenizer)

- **Script is held constant.** Both languages use Devanagari, chosen in Phase 1
  specifically so that script could not confound the resource comparison.
- **Corpus size is nearly matched** — 737.5M against 716.5M training tokens — so the
  H/L distinction here is about *composition*, not volume. Hindi draws on 4 sources
  including two news outlets and Wikipedia; Nepali on 3, with Wikipedia contributing
  only 6,975 documents against Hindi's 41,137.
- **Tokenizer fertility differs by 9.7%** (1.259 against 1.381), which is the direct
  cause of the perplexity/BPB inversion above.
- **A caution on BPB across languages.** At 2.454 and 2.648 UTF-8 bytes per character,
  Devanagari deflates BPB roughly 2.5× relative to Latin-script text at equal
  per-character predictability. These BPB figures are comparable *to each other* and not
  to published English results; bits-per-character is the number to quote across scripts.

## 6. Generation quality

200 held-out prefixes of 64 tokens, 128-token continuations, scored against the
reference continuations (`scripts/eval_generation.py`). BLEU is corpus-level **BLEU-4**
(`bleu_ngram_order: 4`, signature `nrefs:1|case:mixed|eff:no|tok:intl|smooth:exp|version:2.6.0`).

**Model H (Hindi)**

| Decoder | BLEU-4 | chrF | chrF++ | ROUGE-L F1 | Distinct-2 | Rep-4 |
|---|---|---|---|---|---|---|
| greedy | 2.76 | 18.13 | 16.10 | 0.1312 | 0.1330 | 0.7515 |
| **temp 0.5** | **3.78** | 21.90 | 19.84 | **0.1426** | 0.2869 | 0.3910 |
| temp 1.0 | 1.90 | **22.42** | **20.02** | 0.1217 | 0.7213 | 0.0118 |
| temp 1.5 | 0.36 | 19.73 | 16.16 | 0.0631 | 0.9632 | 0.0002 |

**Model L (Nepali)**

| Decoder | BLEU-4 | chrF | chrF++ | ROUGE-L F1 | Distinct-2 | Rep-4 |
|---|---|---|---|---|---|---|
| greedy | 1.60 | 18.49 | 15.76 | 0.0947 | 0.1281 | 0.7968 |
| **temp 0.5** | **2.21** | 22.53 | 19.41 | **0.1107** | 0.3410 | 0.3956 |
| temp 1.0 | 1.31 | **25.10** | **21.13** | 0.0962 | 0.8349 | 0.0123 |
| temp 1.5 | 0.19 | 24.41 | 19.29 | 0.0467 | 0.9727 | 0.0001 |

### Why each metric is or is not informative here

**BLEU-4 is the least informative of the three, and its absolute values should not be
read as quality.** Open-ended continuation has one reference and no requirement that the
model reproduce it; a fluent, on-topic continuation that happens to choose different
words scores near zero on 4-gram overlap. The absolute numbers (0.19–3.78) reflect that
structural mismatch, not the models' fluency. BLEU is still useful *relatively* — it
orders the four decoders consistently for both languages — but a reader comparing 3.78
to translation-task BLEU would draw the wrong conclusion.

**chrF is more informative for these languages, and it disagrees with BLEU.** Character
n-gram overlap is robust to the morphological variation that defeats word-level
matching, which matters for Devanagari where a single stem takes many inflected forms.
It peaks at **temperature 1.0 for both models**, one step above BLEU's and ROUGE-L's
optimum at 0.5. Inspecting the samples, temperature 1.0 output is visibly less coherent —
it drifts off-topic within two sentences — so chrF here is rewarding surface character
diversity rather than quality. **Where the three metrics disagree, BLEU and ROUGE-L
match human reading and chrF does not.**

**ROUGE-L adds the least marginal information.** Its longest-common-subsequence recall
tracks BLEU closely (both peak at 0.5, both collapse at 1.5), so it largely confirms
rather than extends what BLEU shows.

**The diversity statistics are the most diagnostic numbers in the table.** Greedy
decoding has a 4-gram repetition rate of **0.75 (Hindi) and 0.80 (Nepali)** — the
samples show the model looping a single sentence up to seven times. No overlap metric
penalises this adequately: greedy's chrF (18.13) is only 17% below its peak, despite the
output being unusable. Distinct-2 rising 0.13 → 0.96 alongside repetition falling
0.75 → 0.0002 describes the coherence/diversity trade-off far more directly than BLEU
does.

**Both models show the identical ladder shape** — BLEU peaks at 0.5, chrF at 1.0,
repetition collapses monotonically — which is itself evidence that the two runs behaved
consistently under the same recipe. At temperature 1.5 Hindi begins emitting Latin-script
fragments, the sampling tail reaching tokens the model has almost no evidence for.

**Recommended operating point: temperature 0.5** for both models — best BLEU, best
ROUGE-L, and repetition already down to 0.39 from greedy's 0.75.

## 7. Attention analysis

Averaged over 20 evenly-spaced validation batches (`scripts/attention_analysis.py`).
Heatmaps are drawn for layers 0, 3 and 6 — an early, a middle and the final layer — on a
real sentence in each model's own language:

- **Model H:** भारत की राजधानी नई दिल्ली है और यह देश का सबसे बड़ा शहर है।
- **Model L:** नेपालको राजधानी काठमाडौं हो र यो देशको सबैभन्दा ठूलो सहर हो।

### Head census (49 heads each)

| Classification | Model H | Model L |
|---|---|---|
| local | 15 | 16 |
| mixed | 16 | 14 |
| long-range | 1 | 2 |
| diffuse | 17 | 17 |

| | Model H | Model L |
|---|---|---|
| Mean entropy across heads (nats) | 3.208 | 3.255 |
| Mean attention distance (positions) | 63.65 | 64.05 |
| Mean weight on previous token | 0.1181 | 0.1145 |

### The layer arc

Normalised entropy (raw entropy ÷ `ln(t+1)`, so values are comparable across positions),
averaged over the 7 heads in each layer:

| Layer | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| **Model H** | 0.911 | 0.791 | 0.501 | **0.330** | 0.489 | 0.567 | 0.708 |
| **Model L** | 0.920 | 0.832 | 0.531 | 0.477 | **0.398** | 0.516 | 0.690 |

Both models learn the same **U-shape**: diffuse early, sharply specialised in the middle,
broadening again at the output. Mean attention distance follows it inversely — Hindi
105 → 10 → 86 positions, Nepali 103 → 20 → 85.

The interpretation is that early layers do undirected context mixing, middle layers run
precise positional operations on the mixed representation, and late layers re-broaden to
pool evidence for the output distribution.

### Local/positional versus content-based heads

**Positional heads** are unambiguous. Model H's layer 3 carries **two**: head 3 (entropy
0.163 nats, 88.0% of its mass on the immediately preceding token, mean distance 1.37) and
head 4 (0.225 nats, 85.7%, 1.39). These are previous-token copying heads, visible in the
layer-3 figure as clean off-diagonal stripes.

Model L allocates **one, but sharper**: layer 4 head 1 at **0.112 nats and 95.6%**
previous-token mass — the single most specialised head in either model — with the next
sharpest a distant 1.227 nats. Model H spreads the same function across two heads; Model
L concentrates it in one.

**Content-based heads** are the diffuse and long-range ones: Model H's layer 1 head 1
(mean distance 179.4) and Model L's layer 1 head 0 (171.0) attend far and broadly, with
weights depending on what the tokens are rather than where they sit.

**Attention sinks.** Every head in both models places heavy weight on position 0 — the
bright leftmost column in every panel. This is the well-documented sink behaviour: heads
with nothing relevant to attend to park their mass on the first token, which acts as a
no-op. It is the reason raw entropy alone misclassifies heads, and why the classification
uses previous-token share and mean distance alongside it.

### How Model H and Model L differ

1. **Specialisation arrives one layer later in Model L** (minimum at layer 4 against
   layer 3) and is **less deep** (0.398 against 0.330). With the same architecture and
   token budget, the lower-resource model organises marginally more slowly.
2. **Model L concentrates the previous-token function**, Model H distributes it.
3. **Model L keeps one more long-range head** (2 against 1) and one fewer mixed head.
4. **The aggregate statistics are nearly identical** — mean entropy 3.208 against 3.255,
   mean distance 63.65 against 64.05, previous-token share 0.1181 against 0.1145. The
   difference between the two models is in *where* structure sits, not *how much* there
   is.

## 8. Resource-level comparison

| | Model H (Hindi) | Model L (Nepali) |
|---|---|---|
| Training corpus | 737,537,757 tokens | 716,450,642 tokens |
| Documents | 1,021,431 | 1,278,292 |
| Sources | 4 | 3 |
| Manual-collection share (tokens) | 27.91% | 21.87% |
| Tokenizer fertility | 1.259 | 1.381 |
| Epochs trained | 0.710 | 0.730 |
| Validation perplexity | 28.43 | 45.23 |
| Validation bits per byte | 0.4930 | 0.4527 |
| Bits per character | 1.2099 | 1.1991 |
| BLEU-4 @ temp 0.5 | 3.78 | 2.21 |
| chrF @ temp 1.0 | 22.42 | 25.10 |

**The resource gap is real but much smaller than perplexity suggests.** Corpus volume was
nearly matched by design, so this is not a size comparison — it is a comparison of
composition and linguistic structure at equal volume. On the metrics that survive
normalisation, the two models are close: 0.9% apart in bits per character, within 0.05
nats on mean attention entropy, and structurally identical in their layer arcs.

Where the gap is clearest is **generation against a reference**: Model H leads on BLEU-4
(3.78 against 2.21, +71%) and ROUGE-L (0.1426 against 0.1107, +29%) at the same decoder.
That is the measurement most sensitive to whether the model has seen enough text to
reproduce conventional phrasing, and it is where the higher-resource corpus tells.

Three factors plausibly explain why the gap does not show up in per-character loss:

1. **Nepali's corpus is more homogeneous.** Three sources against four, and OnlineKhabar
   alone supplies 21.9% of tokens. Lower diversity means lower entropy — easier to model,
   but less general.
2. **Morphology.** Nepali's longer, more suffix-heavy words mean more of each token is
   predictable from within-word context, which per-character loss rewards.
3. **The token budget binds equally.** At 0.71 and 0.73 epochs both models are
   data-limited rather than capacity-limited, and both were still improving at the end
   (0.048 and 0.053 nats over the final 4,000 steps). The gap being measured is between
   two *undertrained* models; with a larger compute budget it might widen, as Model H has
   more distinct text left to exploit.

**Limitation, stated plainly.** These numbers characterise the compute budget as much as
the architecture. Neither model reached convergence, and the ~25M parameter ceiling was
fixed by the assignment rather than chosen for these corpora.

## 9. Reproduction

```bash
# 1. Phase 1 splits -> packed uint16 token arrays (local, CPU)
python -m scripts.pack_tokens --config hindi/configs/dataset.json
python -m scripts.pack_tokens --config nepali/configs/dataset.json

# 2. Pretraining (GPU, ~3.5 h per language)
python -m scripts.pretrain --lang hi --out-dir checkpoints/hindi --resume
python -m scripts.pretrain --lang ne --out-dir checkpoints/nepali --resume

# 3. Evaluation
python -m scripts.eval_lm         --lang hi --checkpoint checkpoints/hindi/best.pt \
                                  --splits validation test
python -m scripts.eval_generation --lang hi --checkpoint checkpoints/hindi/best.pt \
                                  --num-prompts 200
python -m scripts.attention_analysis --lang hi --checkpoint checkpoints/hindi/best.pt \
                                  --heads 0 1 2 3 4 5 6

# 4. Reporting (local, seconds)
python -m scripts.plot_training --compare
python -m scripts.compare_models

# 5. Verification
python tests/test_causal.py    # 5 checks, including a negative control
python tests/test_model.py     # 8 checks, including the parameter budget
```

`kaggle/README.md` documents the Kaggle path end to end, which is how both runs were
actually executed.
